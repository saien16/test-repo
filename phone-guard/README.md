# 着信ガード 🛡️ — レピュテーション着信拒否アプリ

かかってきた電話番号の**評判（レピュテーション）**を照会し、
**勧誘・詐欺・犯罪**に使われる番号だったら **アプリに履歴を残して、自動で着信拒否**する——
というアイデアを、そのまま体験できる **動くプロトタイプ** です。

外部依存なし・単一HTMLで動作します。データはすべてブラウザ内（localStorage）に保存されます。

## できること

| 機能 | 説明 |
|------|------|
| 📞 着信シミュレート | 番号を入力 or プリセットから「着信」を発生させる |
| 🔍 レピュテーション照会 | 内蔵DB＋ヒューリスティックで `安全 / 勧誘 / 詐欺 / 犯罪 / 不明` に分類し危険度(0-100)を算出 |
| 🚫 自動着信拒否 | 危険と判定した着信を自動で拒否（設定でオン/オフ・種類・しきい値を調整） |
| 📜 履歴 | すべての着信を「番号・分類・危険度・対応・日時・情報源」付きで記録。タップで詳細 |
| 📝 拒否リスト | 手動で番号を登録／解除。DB上の危険番号も一覧 |
| ♻️ 誤判定の報告 | 履歴の詳細から番号の分類を修正 → DBに反映（安全にすると拒否解除） |

## 使い方

```bash
# そのままブラウザで開くだけ（ビルド不要）
open phone-guard/index.html          # macOS
xdg-open phone-guard/index.html      # Linux

# もしくは簡易サーバーで
npx serve phone-guard
```

スマホの縦画面を想定したUIです。ブラウザの開発者ツールでモバイル表示にすると雰囲気が出ます。

### 試してみる
1. ホームのプリセット「特殊詐欺」や「架空請求」をタップ → 照会後に**自動拒否**され、履歴に残ります。
2. 「正規企業」をタップ → **安全**と表示され、応答/拒否を自分で選べます。
3. 設定タブで「自動で着信拒否」をオフにすると、危険でも**警告表示のみ**になります。

## 判定ロジック（`lookup` / `shouldBlock`）
1. ユーザーの手動拒否リストに一致 → 即ブロック
2. 内蔵レピュテーションDBに一致 → その分類・危険度を使用
3. 未登録なら番号種別から推定（国際番号・フリーダイヤル等）
4. `保護ON` かつ `自動拒否ON` かつ `分類が拒否対象` かつ `危険度 ≥ しきい値` → **自動で着信拒否**して履歴に記録

内蔵DBはデモ用の疑似データです。実サービスでは迷惑電話DBや通信事業者・コミュニティ報告のAPIに置き換えます。

## ⚠️ 重要：本物の「着信ブロック」について

これは**仕組みを体験するためのWebプロトタイプ**で、実際の電話回線には接続しません。
ブラウザのWebページは、OSにかかってくる**本当の着信を捕捉・拒否できません**。
実機で本当に着信拒否するには、**ネイティブアプリ**が必要です。

- **Android**: `CallScreeningService`（`RoleManager` で「発信者番号/迷惑電話アプリ」ロールを取得）で
  着信時に番号を受け取り、`CallResponse` で拒否（disallow）できます。
- **iOS**: **Call Directory Extension**（`CXCallDirectoryProvider`）で番号リストを
  ブロック/識別として登録します。着信ごとの動的判定はできず、事前登録した番号リストで判定します。

このプロトタイプの `lookup()`（照会）と `shouldBlock()`（判定）のロジックは、
そのままネイティブ実装のコアとして移植できる形にしています。
