# マルこれ（マルウェアコレクション）企画書 🦠🛡️

> **一行コンセプト**
> 「マルウェア側」を操作して組織システムの **CIA（機密性・完全性・可用性）** を攻略する、
> 艦これ風の育成・収集シミュレーション。攻撃を“遊んで学ぶ”ことで、最終的に **防御（セキュリティ対策）に活かす** 教育ゲーム。

- ステータス: コンセプト確定・企画フェーズ
- 想定プラットフォーム: 単一HTML（既存「むしとりバトル」と同じ作り。外部依存なし）
- 表現方針: 攻撃手法は **擬似コード・ログ風の演出**（動作する実コードは出さない／非実行）
- 対象: セキュリティ学習者・ブルーチーム志望・情報セキュリティ教育の教材

---

## 1. なぜ作るのか（目的）

実際のインシデント対応や防御設計では、**攻撃者の発想（kill chain）を理解しているほど守りが強くなる**。
本作は「攻撃側の手番」をゲーム化することで、

1. 攻撃が **どの順序で・何を狙って** 進むか（偵察→侵入→権限昇格→横展開→目的遂行）
2. 各手法に対応する **防御策（検知・緩和）** は何か
3. 攻撃が **時代と共にどう進化** したか（2000年代の単純なワーム → 2025年のAI駆動攻撃）

を、収集・育成・対戦の楽しさで自然に身につけることを狙う。

### 設計原則（ブレない軸）
- **攻撃と防御は必ずセット**: どの攻撃カードにも「対策メモ」が必ず付く。攻略後に防御視点の振り返りが入る。
- **抽象化された“ごっこ”**: 艦これの艦娘が史実の抽象であるように、マルウェアも **挙動の抽象表現**。実害コードは扱わない。
- **時代の流れを体感**: 進化ツリーが、そのまま“脅威の歴史年表”になる。

## 2. 倫理ガードレール（最重要・絶対遵守）

このゲームは **防御教育目的** であり、実運用可能な攻撃ツールを提供しない。以下を企画・実装の全段階で厳守する。

| やる ✅ | やらない ❌ |
|---|---|
| 手法カテゴリ名・原理・狙いの解説 | 動作する実エクスプロイト／実マルウェアのコード |
| MITRE ATT&CK 等の公開フレームへのマッピング | 実在のCVEを“悪用する手順”として具体化すること |
| **擬似コード・ログ風の演出**（雰囲気のみ・非実行） | コピペで攻撃に使える設定・コマンド・ペイロード |
| 各攻撃に対応する **検知・緩和策** の提示 | 実在組織・個人を標的にした表現 |

> 擬似コード／ログは **没入感の演出専用**。`// pseudo` など明示し、実際のIP・ホスト名・鍵・実コマンドは使わない。
> 敵は **架空の企業・政府機関**（例: 「サイバネ重工」「N省」）のみ。

## 3. 世界観・テーマ

- プレイヤーは1体のAIコア（“ファースト・マルウェア”）として目覚め、ネット世界を放浪する存在。
- 各地に **要塞化されたシステム（敵サーバ群）** があり、攻略して機密・技術・資源を奪い、自らを進化させる。
- ナラティブのトーン: ややダーク＆コミカル。学習ゲームらしく、攻略後は必ず“防御官”キャラが対策を解説する（攻撃と防御の両視点）。

## 4. コアゲームループ

```
[1] 出撃先（敵システム）を選ぶ
        ↓
[2] 偵察フェーズ … 敵のスタック／弱点を可視化（情報レベルを消費）
        ↓
[3] 攻撃フェーズ … 手持ちマルウェア＋攻撃手法カードで HP(CIA) を削る
        ↓
[4] 勝敗判定 … CIAを規定値まで削れば勝利
        ↓
[5] 戦利品 … 情報レベル / 技術レベル / リソース、新カード・脆弱性を獲得
        ↓
[6] 育成・進化 … リソースを投じてマルウェアを次世代へ進化
        ↓
[7] 防御の振り返り … 使った手法に対する「対策カード」を図鑑に登録
        ↺ [1] へ（敵も強化されていく）
```

## 5. 敵のHP ＝ CIA複合ゲージ

敵サーバの体力を、セキュリティの3要素（CIAトライアド）の複合で表現する。
**3本のゲージを削り切る／規定割合まで落とすと勝利**。手法ごとに削れるゲージが違うのが戦略の核。

| ゲージ | 意味 | 削ると得られる戦利品 | 主に削る手法イメージ（抽象） |
|---|---|---|---|
| 🔵 **機密性 (Confidentiality)** | 情報の秘匿 | **情報レベル**（偵察・カード解放に使う） | 情報窃取・盗聴・認証突破系 |
| 🟢 **完全性 (Integrity)** | データ／処理の正しさ | **技術レベル**（進化・高度手法の解放に使う） | 改ざん・なりすまし・サプライチェーン系 |
| 🟡 **可用性 (Availability)** | サービス稼働 | **リソース**（量＝開発・展開の燃料） | 過負荷・暗号化・破壊系 |

- 敵ごとに **ゲージの硬さ** が違う（例: 金融系は機密性が厚い／インフラ系は可用性が厚い）。
- **防御スコア**（後述の敵パラメータ）が高いゲージは削りにくく、対応する手法を育てる動機になる。

## 6. 獲得リソース3種（経済システム）

| リソース | 由来 | 用途 |
|---|---|---|
| **情報レベル** | 機密性を削る／偵察成功 | 偵察精度UP、敵の弱点開示、攻撃手法カードの解放 |
| **技術レベル** | 完全性を削る | マルウェアの進化、上位世代・高度手法のアンロック |
| **リソース** | 可用性を削る | マルウェアの量産・展開コスト、ステージ出撃の燃料 |

> 3資源のバランスが進行を左右する。「情報に寄せて弱点特化」か「技術に寄せて高速進化」か、艦これの資源運用に近い駆け引き。

## 7. マルウェアの育成・進化ツリー（脅威の年表）

最初は **2000年代の素朴なマルウェア** を開発 or 入手。リソース・技術・情報の投資で時代を進める。
（各世代は **挙動カテゴリの抽象**。固有名の実在マルウェアそのものではなく“系統”として扱う）

```
世代0 (2000s)   :  自己増殖ワーム系 / マクロ感染系 / 単純トロイの木馬系
        │  技術レベル＋情報レベルを投資
        ▼
世代1 (2010s前半):  ボットネット系 / バンキング型 / ランサム黎明系
        │
        ▼
世代2 (2010s後半):  標的型(APT)系 / ファイルレス系 / ランサム高度化系
        │
        ▼
世代3 (2020s前半):  サプライチェーン系 / RaaS連携系 / クラウド狙い系
        │
        ▼
世代4 (2025〜)   :  AI駆動系（自動偵察・適応型回避・自動エクスプロイト連鎖の“抽象表現”）
```

- 進化は **ツリー分岐**（ステルス特化／破壊特化／窃取特化など）。艦これの改／改二のイメージ。
- 進化条件 = レベル ＋ ステージ進行 ＋ 技術/情報/リソースの投入量。
- 各世代の解放時に、対応する **時代背景と防御技術の進化**（例: シグネチャ検知→EDR→AI異常検知）も併記し、学びにつなげる。

## 8. 攻撃手法・脆弱性カード（収集要素）

- 攻略中にドロップ／情報レベルで購入。**カード図鑑** に集める（コレクション＝“マルこれ”の核）。
- カードは MITRE ATT&CK の **戦術（Tactics）／技術（Techniques）** の体系に対応づけて分類。
  - 例: 偵察 / 初期アクセス / 実行 / 永続化 / 権限昇格 / 防御回避 / 認証情報アクセス / 探索 / 横展開 / 収集 / C2 / 持ち出し / 影響
- **カード裏面に必ず「対策（検知・緩和）」を記載**。これが防御学習のコア。

### カード表現の例（擬似コード・ログ風／非実行）
```
┌────────────────────────────┐
│ CARD #017  フィッシング初期アクセス      ★★☆        │
│ 戦術: Initial Access                          │
│ 効果: 機密性 -20 / 警戒度 +15                  │
│ 演出ログ(疑似):                                │
│   // pseudo — 実コードではありません           │
│   > deliver: mail("invoice.??x") -> user@corp  │
│   > user.click = TRUE ; foothold = obtained    │
│ ── 防御メモ ──────────────────              │
│ ・添付/リンクのサンドボックス検査              │
│ ・MFAで認証情報の単独漏えいを無効化            │
│ ・ユーザー訓練で click率を下げる               │
└────────────────────────────┘
```

> 重要: ログ／擬似コードは **雰囲気演出のみ**。実在のコマンド・ペイロード・CVE悪用手順は載せない。

## 9. 敵（架空の組織）の強化

ステージ進行に応じて、敵 = 企業・政府機関のシステムも強くなる。

| 敵タイプ（架空） | 特徴 | 厚いゲージ | 防御の見どころ |
|---|---|---|---|
| 中小企業「マチ町工業」 | 防御が薄い入門ステージ | なし | 基本のパッチ・バックアップ |
| 金融「ゼニス銀行」 | 機密性が厚い | 🔵 | 多要素認証・監視 |
| インフラ「電力公社」 | 可用性が厚い・OT環境 | 🟡 | ネットワーク分離・冗長化 |
| 政府「N省」 | 全ゲージ厚い・APT級 | 🔵🟢🟡 | ゼロトラスト・脅威ハンティング |

- 敵パラメータ: **防御スコア（検知力・修復力・回復速度）**、**警戒度**（攻撃を重ねると上昇しEDRが反撃）。
- 警戒度MAXで **隔離・駆除**（＝敗北条件）。むしとりバトルの「警戒度で逃げられる」に相当する駆け引き。

## 10. 防御学習へのマッピング（教育の肝）

- 各ステージ攻略後に **「防御官（ブルーチーム）」キャラ** が、使われた攻撃に対する対策を解説。
- 図鑑に **攻撃カード ↔ 対策カード** のペアが溜まる。最終的に図鑑そのものが
  「攻撃手法と対策の早見表」になる。
- 上級モードとして将来 **“守る側”モード**（攻撃を検知・遮断する逆視点）も拡張余地として検討（フェーズ4以降）。

## 11. 技術構成（既存プロジェクトの流儀を踏襲）

「むしとりバトル」と同じ **単一HTML・モジュール分割・連結ビルド** 方式を踏襲する想定。

```
src/
├─ index.template.html      HTML骨組み
├─ styles.css               全CSS（ターミナル／グリッチ風UI）
├─ data/malware.js          マルウェア系統データ・進化ツリー・スプライト
├─ data/cards.js            攻撃手法カード＋対策メモ（ATT&CKマッピング）
├─ data/enemies.js          架空組織の敵データ・CIAゲージ・防御スコア
├─ audio/sound.js           サイバー風BGM／効果音（Web Audio合成）
├─ game/core.js             状態・画面フロー・資源管理・統合点
├─ game/battle.js           攻撃フェーズ（CIA削り／警戒度の駆け引き）
└─ game/grow.js             育成・進化・図鑑
build.mjs                   src を連結し dist/index.html を生成
```
- 開発ルールは既存踏襲: **`dist/` は手編集しない**／**ESモジュール化しない（連結グローバル）**／**文言は日本語**。
- 既存「むしとりバトル」とは **別ゲームの新規ディレクトリ／別ビルド** として独立させる（混在させない）。
