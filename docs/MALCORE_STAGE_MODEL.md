# マルこれ — ステージ構造：複数サーバ網とターン制限 ⏳🗺️

> フェーズ0-A の設計。ステージは **複数のサーバユニットで構成されるネットワーク網**。
> そのうち1台が **本命（攻略目標）**。プレイヤーは **規定ターン数以内に本命を制圧**できなければ敗北。
> ＝「長居するほどブルーチームの封じ込めが間に合う」という **滞留時間（dwell time）プレッシャー** を核にする。

- 関連: `MALCORE_ATTACK_MODEL.md`（層・ノード遷移）/ `MALCORE_BALANCE.md`（数値）/ `MALCORE_STATUS_CONTROL.md`（監査）
- これにより戦闘が「殴り合い」から **「制限時間内のルート最適化パズル」** に進化する。

---

## 1. ステージ＝サーバ網（グラフ構造）

ステージは複数ノードのグラフ。エッジ＝到達可能経路。**本命**に至る経路上のサーバを足場化して進む。

```
 [外部公開: Webサーバ] ───┐
        │               │
 [外部公開: メールGW] ──[踏み台: 社員PC]──[内部: 部門サーバ]──★[本命: 勘定系DB]
                              │                  │
                        《IDS装置》          《境界FW装置》
```
- 各ノードは `MALCORE_BALANCE.md` の **個別ステータスブロック**（CIA/H/V/防御）を持つ。
- **本命（★）だけが勝利条件**。他サーバは経路・足場・ボーナス源（必ずしも攻略不要）。
- 《装置》ノード（IPS/FW等）は破壊で経路開放／回避で素通り（`MALCORE_DEFENSE_MODEL.md`）。

### ノード種別
| 種別 | 役割 | 攻略の意味 |
|---|---|---|
| 🌐 外部公開 | 入口 | 初期侵害の起点 |
| 💻 踏み台/クライアント | 中継 | 足場化・ボット化で内側へpivot |
| 🏢 内部 | 中間目標 | 権限昇格・横展開の足がかり |
| ★ 本命 | 攻略目標 | CIAを削り切れば **勝利** |
| 《装置》 | 防御 | 回避 or 破壊で経路制御 |

---

## 2. 勝利・敗北条件（2つの“敗北クロック”）

| 条件 | 結果 |
|---|---|
| ✅ **本命のCIAを規定まで削る** | 勝利 |
| ⏳ **制限ターン超過**（本命未制圧） | **敗北**＝ブルーチームが封じ込め完了・追い出し |
| 🚨 **主要層の警戒度 W ≥ 100** | 敗北＝足場一斉駆除でルート寸断 |

> **ターン制限**＝インシデント対応が間に合う締切。**警戒度**＝見つかって追い出される。
> 2つのクロックが同時に進むので「**速く、かつ静かに**」本命へ最短到達する判断が要る。

---

## 3. ターン消費ルール

1ターン＝1手番。以下の主要アクションが1ターンを消費する。

| アクション | ターン | 補足 |
|---|---|---|
| 偵察 | 1 | ノードの防御構成を開示 |
| 初期侵害 / 横展開（pivot） | 1 | 経路を1本進む |
| 足場確立（バックドア/ボット化） | 1 | 以後の再侵入が安定 |
| カットイン発動（偵察/診断/曝露） | 1 | H/V を有利化 |
| 撃破（CIAを削る） | 1 | 本命・サーバへの攻撃 |
| 装置の破壊/回避 | 1 | 経路開放（破壊は警戒度大） |

- **ボットネット規模が大きいと並列行動**（同一ターンに2手）が解禁＝終盤の時短手段（`MALCORE_BALANCE.md` §8 と連動）。
- 寄り道（任意サーバ攻略）は **ターンを食う**が、足場・ボット・偵察ボーナスで本命攻略を時短できる＝投資判断。

## 4. 制限ターン草案（ステージ別）

TTK目安（入門1〜2T／中盤3〜5T／ボス6〜10T）に、ルート移動・偵察・カットインの諸経費を上乗せ。

| 敵 | 層/サーバ数 | 制限ターン | 想定の内訳 |
|---|---|---:|---|
| マチ町工業 | 1台 | **4T** | 偵察1＋撃破2＋余裕1 |
| ゼニス銀行 | 3台＋2装置 | **8T** | 偵察→侵害→足場→pivot→カットイン2→撃破2 |
| 電力公社 | 5台（OT分離） | **10T** | 多段＋装置回避＋短期決戦 |
| N省 | 7台＋ゼロトラスト | **12T** | 監査2T毎の硬化に追われる総力戦 |

> 制限ターンは難度の主ツマミの1つ。短いほど「カットインで一気に通す」プレイを強制する。

## 5. ルート戦略（複数サーバならではの判断）

- **最短突破**: 本命への最短経路だけ攻略。ターン節約だが装置・硬さに正面からぶつかる。
- **足場固め**: 踏み台を複数ボット化してから本命へ。ターンを使うが並列行動・A火力・再侵入冗長性で後半加速。
- **装置破壊ルート**: IPS/FWを壊して経路を開く。速いが警戒度が跳ね、ターン制限より先に警戒度MAXの危険。
- **静音ルート**: 装置を回避で抜ける。警戒度を抑えるがターンを食う。

> 「ターン」「警戒度」「火力」の三すくみを、サーバ網のどこに資源を割くかで解いていく。

---

## 6. 複数サーバの相互作用
- **監査の波及**: 1台が異常検知すると、ネット全体の監査周期が早まる（警戒度が高い網ほど硬化が加速）。
- **足場の連鎖**: 隣接ノードを足場化済みだと、次の横展開コスト/警戒度が減る（地ならし効果）。
- **装置の影響範囲**: 《境界FW》破壊は背後の複数サーバへの経路をまとめて開く＝高リターン高リスク。
- **回復役サーバ**: バックアップ用サーバが生きていると本命のI/Aが回復。先に潰すと本命が脆くなる（優先目標の判断）。

---

## 7. 現実の学び（この制限が教えること）
- **滞留時間（dwell time）と MTTD/MTTR**: 攻撃者が長居するほど検知・対応が間に合う。＝防御は「侵入を防ぐ」だけでなく **「素早く検知し追い出す」** ことが勝敗を分ける、と体感できる。
- **多層・分離の価値**: サーバ網が分離・監視されているほど、攻撃者は本命到達に時間（ターン）を取られる＝なぜネットワーク分離とログ監視が効くかが裏から分かる。
- 防御官の締めセリフ例:「攻撃を**間に合わせなかった**のは、分離と監視と迅速な対応の勝利だ」。

## 8. 戦闘例の更新：ゼニス銀行を8Tで攻略
```
T1 偵察（網と本命の防御を開示）            W+2
T2 フィッシングで社員PCに初期侵害            W+5
T3 MyDoomで社員PCをボット化（足場確立）      W+5
T4 横展開：社員PC→本命（境界FWを回避）       W+2
T5 🔍偵察カットイン：本命H 55→35            W+5
T6 🧪診断カットイン：本命V 35→60            W+5
T7 Zeus撃破：機密性 約99 → C160→61         W+10
T8 Zeus撃破：機密性 約99 → C 0 ✅ 勝利       W+10
                                  累計 W≈44 < 100 ✔ / 8T以内 ✔
```
- カットインを省くと撃破に3T必要＋監査で硬化 → **8Tを超えて敗北**。＝制限ターンがカットイン設計を後押し ✅
- 装置を破壊で抜けると速いが W が跳ね、警戒度クロックが先に切れるリスク ⚠️＝ルート選択に意味が出る ✅
